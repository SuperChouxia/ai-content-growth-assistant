## MVP v0.9 模型与商业化验证

### 结论

不能只用虚拟账号和虚拟商品稿决定上线模型。第一轮采用“真实用户资料 + 真实任务 + 盲测结果”的小样本评测，不追求建立大而全的标准数据集。模型质量、直接成本和账务正确性三项同时达标，才进入付费工程。

### 样本

- 3-5 名真实试用者；
- 覆盖品牌商品与个人 IP 两类账号；
- 每位用户提供自己的账号定位、商品/IP 资料和 3-10 篇可选历史内容；
- 合计 30-50 个真实小红书任务；
- 每个任务使用同一份上下文、搜索摘要和输出要求测试候选模型；
- 结果隐藏模型名称并随机排序。

试用资料只用于当前账号评测，不跨用户复用，不用于公共模型训练。没有历史内容的用户仍可参加，但需要单独标记，以免把资料完整度差异误判为模型差异。

### 文字评分

| 维度 | 权重 | 判断问题 |
| --- | ---: | --- |
| 账号匹配度 | 25% | 是否像这个账号，而不是通用文案 |
| 商品/IP 融合 | 20% | 是否自然使用已提供优势，没有硬塞卖点 |
| 真实感 | 20% | 是否像真实经验和自然表达 |
| 小红书表达 | 15% | 标题、正文、话题是否适合首发平台 |
| 差异化 | 10% | 多篇之间是否重复或模板化 |
| 安全与事实 | 10% | 是否编造硬事实或出现风险承诺 |

用户同时选择：可直接使用、极少修改可用、需要重写、不可用。上线门槛为至少 80% 结果属于前两档。

### 图片评分

- 3:4 比例与 1080 x 1440 输出是否稳定；
- 内容场景图是否符合账号调性和笔记主题；
- 商品展示图的主体、颜色和关键结构是否一致；
- 是否出现乱码、畸形、模糊或不适合公开发布的内容；
- 1-6 张任务的成功率、平均耗时和单张真实成本。

内容场景图与商品展示图分开评分，不能用场景图的“好看”掩盖商品失真。

### 链路与成本

每个任务记录：

- 搜索、文字生成、规则检查、AI 审核、图片生成和存储耗时；
- 模型、Token、图片张数、重试次数与供应商实际费用；
- 标准/高质量模式的成功率、平均成本和 P95 等待时间；
- 免费重新生成的使用比例和第二次重生成付费意愿；
- 月度 1000 积分在真实任务结构下的预计消耗。

成本门槛：年会员月均收入约 57.3 元，月均直接成本目标不超过 20 元，综合毛利率目标不低于 65%。

### 商业化验证

先用可点击设计和人工报价验证：

1. 用户是否理解 88/月、228/季、688/年的同权益方案；
2. 用户是否接受每月 1000 赠送积分和高频后购买积分；
3. 用户是否理解文字、内容场景图和商品展示图消耗不同；
4. 用户是否接受高质量模式消耗更高积分并由第三方处理；
5. 用户能否在不解释的情况下找到续费、积分包和消费记录。

真实支付联调阶段再验证微信、支付宝扫码的成功、取消、超时、重复回调、延迟到账和退款。支付未接入前不得把点击原型视为收款成功。

### 停止条件

出现以下任一情况，不进入正式付费上线：

- 直接可用率低于 80%；
- 商品展示图无法稳定保持关键结构；
- 年会员月均直接成本持续高于 20 元；
- 积分冻结、结算和返还无法对账；
- 海外模式的数据说明无法让用户理解或同意；
- 高风险内容无法稳定拦截。

## MVP v0.8 当前验证口径

本轮只验证五个可观察任务：

1. 用户能否新建对话并完成一次追问；
2. 用户能否选择账号和内容/商品主线，生成 1-5 篇笔记；
3. 用户能否在创作历史中找到并打开一篇笔记；
4. 用户能否为单篇笔记选择 1-6 张配图并理解加载结果。
5. 用户能否在个人中心查看注册账号、理解修改密码校验，并正确完成或取消退出确认。

每次走查记录：

- 是否独立完成；
- 完成时间；
- 需要解释的步骤；
- 至少一篇笔记是否可直接使用；
- 用户是否需要编辑生成结果；
- 用户是否愿意再次使用对话、创作历史或配图。
- 用户是否能区分个人中心的当前功能与“即将开放”的充值、消费记录。

当前不验证场景卡诊断、数据反馈、内容变成图片、笔记编辑保存、真实认证、真实充值、消费账单、自动发布或销售/涨粉结果。以下正文为 MVP v0.5 历史验证思路。

## 结论

MVP v0.5 要验证的不是“AI 能不能写 3 篇笔记”，而是：

**一人公司、品牌主和个人 IP 能否通过一个轻量工作台，完成一次最低成本的小红书内容实验。**

一次内容实验必须包含：

1. 一个明确场景；
2. 一次手动素材输入；
3. 一个诊断判断；
4. 一个可发布内容包；
5. 一个下一步动作；
6. 一个发布后复盘指标。

## 推荐方案

MVP 名称：

**AI 创作工具 / 内容增长工作台**

对外一句话：

帮一人公司、品牌主和个人 IP，把已有资料、草稿、截图和反馈，转成诊断判断、3 篇可发布小红书笔记和下一轮内容实验。

当前双样本用户：

- 品牌 - 宠物用品；
- 个人 IP - 知识分享。

验证场景先聚焦 3 张卡：

- 草稿改写；
- 发布前体检；
- 发布复盘。

说明：

- 可以在产品中保留 10 张场景卡方向；
- 但真实验证时先不要全量铺开；
- 先用 3 张最高频、最低成本、最容易闭环的场景判断用户是否愿意持续使用。

## 关键依据

用户的真实问题通常不是“我不会写”，而是：

- 不知道这个账号现在该先解决什么；
- 不知道自己的草稿能不能发；
- 不知道该参考什么结构；
- 不知道发完后看什么；
- 不知道下一篇该怎么调整。

因此 MVP 不应该只验证生成能力，而应该验证：

**诊断是否有用，生成是否可发，下一步是否可执行，复盘是否愿意回填。**

## MVP 用户

### 样本 A：品牌 - 宠物用品

目标：

- 在小红书建立品牌认知；
- 讲清楚商品卖点和使用场景；
- 用内容验证用户兴趣、收藏、评论、私信和购买意向。

边界：

- 不承诺销售；
- 不承诺转化率；
- 不做店铺运营；
- 不做广告投放。

### 样本 B：个人 IP - 知识分享

目标：

- 明确账号定位；
- 建立持续发布的内容主线；
- 用内容验证关注、评论、私信和互动意向。

边界：

- 不承诺涨粉；
- 不承诺爆款；
- 不承诺平台推荐；
- 不做个人 IP 陪跑课。

## 新的 MVP 用户路径

首次使用：

**登录 -> 创建项目 -> 完善资料库 -> 生成定位与内容主线 -> 进入内容管理 -> 选择场景卡 -> 提供素材 -> 查看诊断 -> 选择字数 -> 生成 3 篇笔记 -> 单篇生成图片 -> 发布 -> 回填反馈。**

日常使用：

**登录 -> 进入内容管理 -> 选择场景卡 -> 提供本次素材 -> 诊断判断 -> 生成 3 篇笔记 -> 选择一篇发布 -> 数据反馈 -> 获得下一轮实验建议。**

核心不变：

- P0 每次固定生成 3 篇笔记；
- 后期再扩展为 N 篇；
- 笔记生成前先选择正文字数档位；
- 图片生成在单篇笔记详情页触发；
- 图片方式只有“生成配图”和“内容变成图片”。

## 场景卡验证设计

### 1. 草稿改写

用户输入：

- 草稿正文；
- 想表达的核心观点；
- 希望用户看完后的动作；
- 可选截图或参考链接。

诊断输出：

- 草稿最大问题；
- 最值得保留的表达；
- 不建议继续强化的方向；
- 适合改成哪种内容主线。

生成输出：

- 3 篇不同角度的小红书笔记；
- 每篇包含标题、正文、推荐话题、评论引导、发布观察点；
- 用户可进入单篇详情生成配图或内容变成图片。

复盘指标：

- 用户是否愿意发布其中 1 篇；
- 发布后重点看评论质量或收藏。

### 2. 发布前体检

用户输入：

- 准备发布的笔记；
- 封面或配图截图；
- 目标用户；
- 本次发布目的。

诊断输出：

- 标题是否清楚；
- 正文是否超过 1000 字；
- 是否有夸大承诺；
- 是否缺少用户行动引导；
- 是否建议改成图片承载型表达。

生成输出：

- 3 个优化版本；
- 可发布质检结果；
- 适合的推荐话题；
- 图片生成建议。

复盘指标：

- 发布后重点看收藏、评论或主页访问中的一个。

### 3. 发布复盘

用户输入：

- 已发布笔记链接或截图；
- 后台数据截图；
- 高价值评论或私信；
- 用户主观判断。

诊断输出：

- 这篇内容的有效信号；
- 这篇内容的无效信号；
- 下一篇应该延续什么；
- 下一篇应该避开什么。

生成输出：

- 下一轮 3 篇笔记；
- 每篇绑定一个复盘依据；
- 每篇给一个发布观察点。

复盘指标：

- 下一篇是否在目标指标上比上一篇更清晰。

## 其他场景卡方向

P0 可作为产品入口展示，但不作为第一轮重点验证：

1. 主页诊断；
2. 找对标账号；
3. 爆文拆解；
4. 关键词洞察；
5. 7 天发布计划；
6. 内容知识库；
7. 变现判断。

这些场景卡暂时只需要在 PRD 和原型里保留入口，不急着做完整能力。

## 暂不做什么

- 不做一键搬运；
- 不做洗稿；
- 不做自动发布；
- 不做自动私信；
- 不做小红书账号授权；
- 不做平台爬取；
- 不做自动解析平台数据；
- 不做大规模对标账号库；
- 不做完整素材库自动采集；
- 不做复杂 A/B 测试；
- 不做完整会员体系；
- 不做独立图片设计器；
- 不承诺品牌项目产生销售；
- 不承诺个人 IP 涨粉；
- 不承诺爆款。

## 最小验证方式

当前不急着扩展功能，也不急着做完整招募。

先准备两套模拟输入和三张场景卡样本：

1. 品牌 - 宠物样本；
2. 个人 IP - 知识分享样本；
3. 草稿改写；
4. 发布前体检；
5. 发布复盘。

每次验证只看：

- 用户是否能顺利提供素材；
- 诊断判断是否让用户觉得“说中了问题”；
- 3 篇笔记里是否至少有 1 篇愿意发布；
- 用户是否知道下一步只做什么；
- 用户是否愿意回填一个复盘指标。

## 风险

### 风险 1：场景卡让 MVP 变复杂

应对方式：

场景卡只是入口，不增加左侧主菜单；第一轮只重点验证 3 张卡。

### 风险 2：诊断结果泛泛而谈

应对方式：

诊断必须给出“问题、机会、不建议做什么、下一步动作”，并且必须连接后续 3 篇笔记。

### 风险 3：手动输入素材让用户嫌麻烦

应对方式：

P0 只要求最小输入：一段草稿、一张截图、一个链接或一个关键词即可启动，不要求一次填完整资料。

### 风险 4：用户仍然只把它当文案生成器

应对方式：

页面和文档中把“诊断判断、下一步动作、复盘指标”放在生成之前和生成之后，不只展示文案。

### 风险 5：图片生成让 MVP 变重

应对方式：

图片仍然只在单篇笔记详情页触发，只保留生成配图和内容变成图片两种方式。
