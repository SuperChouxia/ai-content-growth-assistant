# 内容获客定位助手 - MVP 验证方案

更新日期：2026-06-11

当前状态：MVP 验证草稿。

说明：这份文档只用于定义“先验证什么、怎么判断是否值得继续”。当前仍不进入产品设计、开发，也不展开首批用户招募、交付和复盘执行。

## 结论

第一版 MVP 不做完整 SaaS，也不先做重服务包。

当前先验证一个更小的问题：

**同一套“小红书定位 + 内容主线 + 选题 + 笔记草稿”流程，能否同时支持品牌和个人 IP 两类项目。**

P0 先用两个细分样本验证：

- 品牌 - 宠物；
- 个人 IP - 知识分享。

这两类用户可以一起使用同一个小 MVP，因为底层问题相同：

- 不知道账号该怎么定位；
- 不知道产品、服务或专业能力该怎么讲；
- 不知道该参考谁；
- 不知道第一批笔记该写什么；
- 希望 AI 提效，但又不想写成泛泛的爆款文案。

但两类用户的验证目标必须分开：

- 品牌项目不承诺销售，只验证品牌表达、商品卖点、种草内容和购买意向；
- 个人 IP 不承诺涨粉，只验证账号定位、内容主线、互动意向和持续发布意愿。

## 推荐方案

### MVP 名称

小红书定位与内容验证助手

### 对外一句话

帮有品牌、产品或个人专业能力的人，先讲清楚自己是谁、卖点是什么、该发什么，再生成可测试的选题和笔记草稿。

### 当前双样本用户

样本 A：品牌 - 宠物

- 有自己的品牌和商品；
- 希望在小红书建立品牌认知；
- 希望内容能承接商品种草和用户信任；
- 不承诺销量，只观察内容是否能激发兴趣、收藏、评论和购买意向。

样本 B：个人 IP

- 有专业能力、经历、观点或服务方向；
- 希望在小红书持续发布笔记；
- 希望通过内容吸引关注、互动或私信；
- 不承诺涨粉，只观察定位是否更清晰、内容是否更容易发布、互动是否更精准。

## MVP 要验证什么

### 假设 1：同一套流程可以服务两类用户

共用流程：

1. 收集用户资料；
2. 做账号定位；
3. 拆内容主线；
4. 生成选题；
5. P0 生成 3 篇笔记草稿；
6. 收集用户反馈。

需要验证：

- 品牌和个人 IP 是否都能理解这套流程；
- 两类用户需要的输入字段是否能保持足够轻；
- 输出是否能同时做到“结构一致”和“表达差异化”。

### 假设 1.1：生成数量可以先固定 3 篇，后期扩展为 N 篇

需要验证：

- P0 固定 3 篇是否足够用户拿去测试；
- 用户是否会要求更多或更少篇数；
- 生成数量是否应该在后期做成可配置变量。

### 假设 2：用户真正需要的是定位判断，不只是 AI 写文案

需要验证：

- 用户是否觉得账号定位比之前更清楚；
- 用户是否能说出“我接下来该围绕什么内容持续发”；
- 用户是否愿意基于输出内容去修改、发布和复盘。

### 假设 3：MVP 价值不依赖销售或涨粉承诺

需要验证：

- 品牌项目是否认可“先把商品卖点和使用场景讲清楚”本身有价值；
- 个人 IP 是否认可“先把账号定位和内容主线讲清楚”本身有价值；
- 用户是否能接受第一阶段只验证内容表达和发布反馈，不承诺商业结果。

### 假设 4：正文承载型和图片承载型都需要支持

需要验证：

- 用户是否会把主要表达放在正文；
- 用户是否会把长文、教程、清单或案例拆到图片页里；
- 图片承载型是否能解决小红书正文最多 1000 字的限制；
- 用户是否能理解“正文精简版 + 图片页结构”的输出形式。

## 首版交付范围

### 共同交付

1. 账号一句话定位
2. 目标用户画像
3. 核心卖点或专业优势拆解
4. 3 条内容主线
5. 20 个小红书选题
6. P0 生成 3 篇笔记草稿
7. 对标账号参考方向
8. 发布后的观察指标

### 品牌样本额外交付

- 商品核心卖点拆解；
- 用户使用场景拆解；
- 种草内容角度；
- 品牌信任表达；
- 评论区购买意向观察点。

### 个人 IP 样本额外交付

- 人设边界；
- 专业能力表达；
- 观点和经历内容化；
- 互动引导方式；
- 关注和私信意向观察点。

## 暂不做什么

- 不承诺品牌项目产生销售；
- 不承诺个人 IP 涨粉；
- 不承诺爆款；
- 不做一键搬运；
- 不做洗稿；
- 不做自动发布；
- 不做自动私信；
- 不做店铺运营；
- 不做广告投放；
- 不做完整代运营。

## 验证指标

### 共同指标

MVP 可以继续推进的信号：

- 用户认为账号定位比之前更清楚；
- 用户认为 20 个选题里至少 70% 可以继续修改或发布；
- 3 篇笔记草稿的用户修改量低于 40%；
- 用户愿意至少发布 1-3 篇内容进行测试；
- 用户愿意提供发布后的基础反馈。

MVP 需要调整的信号：

- 用户只认可文案，不认可定位判断；
- 用户觉得资料填写太重；
- 选题看起来正确，但没有发布欲望；
- 笔记像通用 AI 文案，不像自己的品牌、商品、经历或专业表达。

### 品牌项目指标

重点观察：

- 商品卖点是否被讲清楚；
- 内容是否能落到真实养宠场景；
- 用户是否认为笔记可以代表品牌调性；
- 评论、收藏、私信、商品咨询只作为购买意向参考，不作为销售承诺。

### 个人 IP 指标

重点观察：

- 账号定位是否更容易被一句话说清；
- 内容主线是否能支撑持续发布；
- 笔记是否体现个人经历、观点或专业能力；
- 关注、评论、私信只作为互动意向参考，不作为涨粉承诺。

## 最小验证方式

当前不急着扩展功能，也不急着做完整招募。

先准备两套模拟输入和输出模板：

1. 品牌 - 宠物样本；
2. 个人 IP - 知识分享样本。

用这两套样本检查：

- 输入字段是否过重；
- 输出结构是否清楚；
- 两类用户是否能共用同一套产品骨架；
- 哪些内容必须做成行业模板；
- 哪些内容必须保留人工判断。

## 风险

### 风险 1：两个样本让产品变散

应对方式：

共用流程不变，只在输出模板里区分品牌和个人 IP，并通过细分方向适配宠物、餐饮、美妆、育儿等后续场景。

### 风险 2：品牌项目误解成销售承诺

应对方式：

明确表达这是品牌内容和种草表达验证，不承诺销量、转化率或店铺增长。

### 风险 3：个人 IP 误解成涨粉工具

应对方式：

明确表达这是定位和内容主线验证，不承诺涨粉、爆款或平台推荐。

### 风险 4：AI 文案感太强

应对方式：

输出必须绑定用户自己的产品、服务、经历、案例和表达风格，不能只生成通用模板。

### 风险 5：长内容硬塞正文导致不可发布

应对方式：

小红书正文最多 1000 字；如果内容需要更长表达，改用图片承载型，输出正文精简版和图片页结构。

## 下一步

1. 用 1 个品牌样本和 1 个个人 IP 样本先跑通文档层验证；
2. 检查资料采集表是否够轻、够准确；
3. 检查标准交付模板是否能产出 3 篇可发布测试的图文笔记；
4. 再决定是否进入真实用户测试、产品设计或开发。
