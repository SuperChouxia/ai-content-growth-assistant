# AI 创作工具 / 内容增长工作台 - MVP v0.5 PRD

更新日期：2026-07-01

文档版本：MVP v0.5

当前状态：PRD 草案。

说明：本文用于固化当前 MVP 产品功能方案。当前只到产品需求文档，不进入产品设计、开发，也不展开首批用户招募、交付或复盘执行。

## 结论

MVP v0.5 不再把产品定义成普通 AI 写稿工具，而是定义成面向一人公司、品牌主和个人 IP 的小红书内容增长工作台。

核心目标：

**让用户每次登录后，都能基于自己的项目资料和本次手动素材，先获得诊断判断，再生成 3 篇能发的小红书笔记，并可为单篇笔记生成配图或把内容变成图片。**

说明：

- P0 每次固定生成 3 篇；
- 后期可扩展为 N 篇生成数量；
- 内容管理前置增加场景卡入口；
- 场景卡先诊断，再生成；
- P0 素材入口为用户手动输入链接、截图、草稿、关键词和后台数据截图；
- 用户先选择正文字数档位并生成笔记内容；
- 笔记生成后，再选择是否生成图片；
- 图片生成方式分为“生成配图”和“内容变成图片”。

产品左侧主菜单只保留 3 个：

1. 项目管理；
2. 内容管理；
3. 数据反馈。

登录页单独存在。资料库属于项目管理内部，场景卡、生成任务、任务历史和笔记详情属于内容管理内部。

## 产品一句话

帮一人公司、品牌主和个人 IP，把长期资料、草稿、截图、关键词和反馈，转成诊断判断、3 篇可发布小红书笔记和下一轮内容实验。

## MVP 用户

### 样本 A：品牌 - 宠物用品

用户目标：

- 在小红书建立品牌认知；
- 讲清楚商品卖点和使用场景；
- 用内容验证用户兴趣、收藏、评论和购买意向。

产品边界：

- 不承诺销售；
- 不承诺转化率；
- 不做店铺运营；
- 不做广告投放。

### 样本 B：个人 IP - 知识分享

用户目标：

- 明确账号定位；
- 建立持续发布的内容主线；
- 用内容验证关注、评论、私信和互动意向。

产品边界：

- 不承诺涨粉；
- 不承诺爆款；
- 不承诺平台推荐；
- 不做个人 IP 陪跑课。

## 产品主流程

首次使用：

**登录/注册 -> 创建项目 -> 选择项目大类和细分方向 -> 初始化资料库 -> 生成定位和内容主线 -> 进入内容管理 -> 选择场景卡 -> 手动提供素材 -> 查看诊断判断 -> 选择字数档位 -> 生成本次 3 篇笔记 -> 选择单篇笔记生成图片。**

后续使用：

**登录 -> 进入项目 -> 进入内容管理 -> 选择场景卡 -> 提供本次链接/截图/草稿/关键词/后台数据截图 -> 诊断判断 -> 选择字数档位 -> 生成 3 篇笔记 -> 选择单篇笔记生成图片 -> 保存任务历史 -> 回填发布反馈 -> 获得下一轮实验建议。**

核心原则：

- 资料库是长期资产；
- 项目大类初始化后不可更改；
- 细分方向用于控制字段示例、选题角度、话题和图片生成方向；
- 内容管理先用场景卡降低启动成本，再进入生成任务；
- 场景卡必须先输出诊断判断，再进入 3 篇笔记生成；
- 内容管理 P0 每次生成本轮 3 篇笔记，后期可扩展为 N 篇；
- 笔记生成前只让用户选择字数档位，不再前置区分笔记类型；
- 图片生成在笔记生成后作为二次动作；
- 数据反馈区只做手动记录和优化建议，不自动抓取平台数据；
- 每次任务只输出一个可发布内容包、一个下一步动作、一个复盘指标。

## 信息架构

### 独立页面：登录

作用：识别用户，保存项目、资料、生成记录和反馈。

P0 必做：

- 用户注册；
- 用户登录；
- 用户退出；
- 登录后进入个人工作区；
- 保存用户项目和历史数据。

P0 登录方式建议：

- 手机号 + 验证码；
- 或邮箱 + 密码。

二选一即可，P0 不需要同时做多种登录方式。

暂不做：

- 微信登录；
- 小红书账号授权；
- 会员套餐；
- 支付；
- 团队权限；
- 邀请协作；
- 多角色后台。

验收标准：

- 用户能注册并登录；
- 用户重新登录后能看到自己的项目；
- 不同用户之间数据隔离；
- 退出登录后不能查看原工作区数据。

### 主菜单 1：项目管理

作用：管理内容项目，决定项目使用哪套资料字段和生成模板。

P0 必做：

- 新建项目；
- 选择项目大类；
- 选择细分方向；
- 查看项目列表；
- 进入项目；
- 修改项目名称；
- 删除项目。

项目大类：

- 品牌；
- 个人 IP。

项目大类初始化后不可更改：

- 项目大类；
- 项目底层模板；
- 核心业务场景分类。

细分方向：

品牌方向：

- P0 样本：宠物；
- 后期可扩展：餐饮、美妆、母婴、本地生活、其他。

个人 IP 方向：

- P0 样本：知识分享；
- 后期可扩展：美妆、育儿、职场、情感、其他。

细分方向规则：

- P0 可以先作为项目标签和生成提示；
- 后期扩展时可用于控制资料字段、选题模板、话题推荐和图片生成方向；
- 如果细分方向变化较大，应提示用户重新生成定位和内容主线。

创建后可更改：

- 项目名称；
- 账号名称；
- 品牌介绍；
- 商品资料；
- 个人资料；
- 目标用户；
- 内容禁区；
- 对标账号；
- 素材条件；
- 细分方向。

选错项目大类的处理：

- 不允许直接修改项目大类；
- 用户可以新建项目；
- P1 可考虑“复制为新项目”。

验收标准：

- 用户至少能创建 1 个项目；
- 创建项目时必须选择品牌或个人 IP；
- 创建项目时可以选择细分方向；
- 项目创建后，项目大类不可编辑；
- 项目列表能显示项目名称、项目大类、细分方向、最近生成时间。

### 项目管理内部：资料库

作用：沉淀长期资产，避免用户每次生成都重新填写。

资料库包含 6 组内容，且每组都必须可编辑：

1. 基础资料；
2. 品牌/个人 IP 资料；
3. 内容偏好；
4. 素材条件；
5. 对标参考；
6. 生成约束。

#### 3.1 基础资料

共同字段：

- 账号/品牌名称；
- 项目大类；
- 细分方向；
- 小红书账号链接或截图；
- 目标用户；
- 当前内容问题；
- 希望用户看完后的动作；
- 内容禁区；
- 可用素材。

#### 3.2 品牌/个人 IP 资料

品牌字段：

- 品牌定位；
- 主推商品；
- 商品卖点；
- 适用品类或消费场景；
- 使用场景；
- 购买渠道；
- 品牌信任来源。

个人 IP 字段：

- IP 细分方向；
- 身份标签；
- 专业能力；
- 真实经历；
- 核心观点；
- 产品或服务；
- 人设边界；
- 可信任素材。

#### 3.3 定位与内容主线

系统根据资料库生成，并允许用户编辑保存：

- 账号一句话定位；
- 目标用户；
- 核心卖点或专业优势；
- 差异化表达；
- 内容边界；
- 不建议做的方向。

验收标准：

- 定位必须能被一句话说清；
- 品牌项目必须体现商品、场景和品牌信任；
- 个人 IP 必须体现经历、观点和专业能力；
- 不得出现销售、涨粉或爆款承诺；
- 用户编辑后，后续生成任务默认读取最新版定位。

说明：

- 定位与内容主线仍属于项目管理内部能力；
- 可从资料库保存后生成；
- 资料库更新后应提示用户重新生成或确认是否沿用旧定位。

#### 3.4 内容偏好

内容偏好用于每次生成任务复用。

包含：

- 内容主线；
- 话题偏好；
- 禁用词；
- 风格偏好；
- 用户案例或商品场景。

#### 3.5 素材条件

素材条件用于决定生成配图和内容变成图片结果是否具体可执行。

素材条件字段：

- 是否有产品实拍；
- 是否有使用前后对比；
- 是否有截图；
- 是否有人物、宠物或门店出镜；
- 是否有品牌视觉规范；
- 是否有禁止使用的素材；
- 当前最容易补拍或补做的素材。

内容主线默认 3 条。

品牌默认主线：

1. 场景种草；
2. 问题解决；
3. 品牌信任。

个人 IP 默认主线：

1. 经历故事；
2. 专业判断；
3. 方法拆解。

说明：

- P0 先以内置样本支持“品牌-宠物”和“个人 IP-知识分享”；
- 后期扩展餐饮、美妆、育儿等方向时，内容主线可以基于细分方向生成不同模板。

#### 3.6 对标参考

对标参考 P0 只做手动录入和结构拆解：

- 对标账号名；
- 链接或截图；
- 可学习标题结构；
- 可学习内容结构；
- 不建议照搬点；
- 适合本项目的改写方向。

暂不做：

- 自动抓取对标账号；
- 自动采集平台数据；
- 一键搬运爆款内容。

#### 3.7 生成约束

用于控制每次输出质量。

包含：

- 标题默认不超过 20 个字；
- 小红书正文最多 1000 字；
- 正文字数档位；
- 图片生成方式；
- 内容变成图片时的正文精简版；
- 内容变成图片时的图片页结构建议；
- 话题相关性要求；
- 封面图生成要求；
- 配图生成要求；
- 不得夸大承诺；
- 不得伪造案例。

验收标准：

- 资料库内容可编辑、可保存；
- 内容管理每次生成必须读取资料库；
- 用户能看到资料库最后更新时间；
- 资料库缺关键字段时，内容管理应提示补充。

### 主菜单 2：内容管理

作用：用户从具体内容场景进入，先获得诊断判断，再生成一组能发的小红书笔记，并在笔记生成后继续生成图片。

说明：

- P0 每次固定生成 3 篇；
- 后期可扩展为 N 篇，由用户选择或系统推荐生成数量。

内容管理包含 6 个模块：

1. 场景卡入口；
2. 手动素材输入；
3. 诊断结果；
4. 生成任务；
5. 笔记图片生成；
6. 任务历史。

#### 4.1 场景卡入口

场景卡是内容管理的启动入口，不是新的一级菜单。

P0 建议展示 10 张场景卡：

1. 主页诊断；
2. 找对标账号；
3. 爆文拆解；
4. 关键词洞察；
5. 草稿改写；
6. 发布前体检；
7. 7 天发布计划；
8. 发布复盘；
9. 内容知识库；
10. 变现判断。

第一轮最小验证优先跑 3 张：

- 草稿改写；
- 发布前体检；
- 发布复盘。

场景卡统一要求：

- 说明本场景需要用户提供哪些素材；
- 说明本场景会使用哪些资料库内容；
- 说明本场景预计输出什么；
- 不承诺自动抓取平台数据；
- 不把对标账号作为搬运入口。

验收标准：

- 用户能从内容管理选择一张场景卡；
- 用户能看懂每张卡需要提供什么素材；
- 选择场景卡后进入素材输入和诊断流程；
- 场景卡不得绕过“选择字数 -> 生成 3 篇笔记”的主闭环。

#### 4.2 手动素材输入

P0 不做平台爬取和自动解析，素材由用户手动提供。

可输入素材：

- 小红书主页链接或截图；
- 对标账号链接或截图；
- 单篇爆文链接或截图；
- 用户自己的草稿；
- 关键词；
- 评论区截图；
- 小红书后台数据截图；
- 用户主观备注。

验收标准：

- 每次任务至少需要一种素材即可启动；
- 系统应提示“素材越完整，诊断越具体”；
- 用户可以跳过非必填素材；
- 上传截图或粘贴链接都只作为本次诊断素材，不代表系统自动抓取数据。

#### 4.3 诊断结果

诊断是场景卡的核心价值，必须出现在生成笔记之前。

每次诊断至少输出：

- 当前判断：这次最主要的问题或机会；
- 可用素材：哪些输入可直接用于生成；
- 风险提醒：哪些内容不建议照搬、不建议夸大或不建议发布；
- 生成方向：建议本次 3 篇笔记分别从哪些角度展开；
- 下一步动作：用户接下来只需要做的一件事；
- 复盘指标：发布后优先观察的一个指标。

验收标准：

- 诊断结果必须能解释为什么建议这样生成；
- 诊断结果必须能连接后续生成任务；
- 诊断结果不得只给泛泛建议；
- 诊断结果不得承诺涨粉、销售或爆款。

#### 4.4 内容主线

从资料库读取并展示。

用户可以：

- 查看 3 条长期内容主线；
- 选择本次生成要优先参考哪条主线；
- 查看每条主线适合什么用户、解决什么问题、不适合怎么写。

验收标准：

- 每个项目至少有 3 条内容主线；
- 每条主线能被生成任务引用；
- 每次生成的 3 篇笔记必须至少绑定 1 条内容主线。

#### 4.5 生成任务

用户每次新建一个生成任务。

任务输入：

- 已选择的场景卡；
- 诊断结果摘要；
- 本次内容目的；
- 选择内容主线；
- 生成数量；
- 正文字数档位；
- 笔记风格；
- 本次想强调的商品、经历或观点；
- 本次想避开的内容；
- 本次可用素材或素材限制；
- 是否参考上一次反馈建议。

内容目的可选：

- 建立认知；
- 解决疑问；
- 建立信任；
- 激发收藏；
- 引导评论；
- 引导私信；
- 商品种草；
- 关注互动。

生成数量：

- P0 默认值：3 篇；
- P0 不开放自定义数量；
- 后期可扩展为 N 篇，例如 1-10 篇或按任务自动推荐。

正文字数档位：

| 档位 | 建议字数 | 适合内容 |
| --- | --- | --- |
| 短正文 | 200-400 字 | 轻种草、轻观点、互动 |
| 标准正文 | 500-700 字 | 经验分享、问题解决、产品场景 |
| 长正文 | 800-1000 字 | 案例复盘、深度拆解、专业内容 |

说明：

- 小红书正文最多 1000 字；
- 笔记生成前只选择字数档位；
- 不再要求用户先理解复杂的笔记类型；
- 如果后续选择“内容变成图片”，系统再自动生成正文精简版和图片页结构。

每个任务固定输出：

**P0 固定 3 篇小红书笔记。**

每篇笔记包含：

- 标题；
- 正文；
- 正文字数档位；
- 当前字数；
- 推荐话题；
- 评论引导；
- 发布观察点；
- 本篇对应的诊断依据；
- 本篇发布后优先观察的一个指标。

标题要求：

- 默认不超过 20 个字；
- 不使用绝对化、夸大化表达；
- 不直接复制对标账号标题。

推荐话题：

- 每篇推荐 5-8 个话题；
- 话题分为核心话题、场景话题、热门话题；
- 每个话题必须给推荐理由；
- 热门话题必须和正文相关，不强行蹭热点。

可发布质检：

- 标题是否超过 20 个字；
- 正文是否超过 1000 字；
- 正文是否符合所选字数档位；
- 是否包含热门话题和发布观察点；
- 是否出现销售、涨粉、爆款或绝对化承诺。

验收标准：

- 用户能新建生成任务；
- P0 每次任务固定生成 3 篇笔记；
- 后期可扩展为 N 篇生成数量；
- 3 篇笔记不得完全重复角度；
- 每篇笔记都能人工编辑；
- 每篇笔记都能保存为草稿；
- 每篇笔记必须绑定项目资料、定位和内容主线；
- 每篇笔记必须绑定场景卡和诊断结果；
- 每篇笔记必须明确正文字数档位；
- 每篇笔记正文不得超过 1000 字；
- 每篇笔记必须显示可发布质检结果；
- 每篇笔记不得承诺销售、涨粉或爆款。

#### 4.6 笔记图片生成

用户在单篇笔记生成后，再决定是否生成图片。

图片生成入口：

- 笔记详情页；
- 任务历史中的单篇笔记；
- 优化建议后再次编辑笔记时。

图片生成方式：

1. 生成配图；
2. 内容变成图片。

生成配图：

适合正文已经能讲清楚，图片用于提升小红书发布完整度。

输出：

- 封面图；
- 3-6 张配图；
- 每张图的用途、画面主体、构图建议和生成提示；
- 可导出图片。

规则：

- 品牌项目优先使用用户提供的产品图、使用场景图和品牌素材；
- 不凭空生成虚假的品牌商品图；
- 个人 IP 可以生成文字封面、流程图、清单图和场景辅助图；
- 图片风格默认服务小红书图文发布，不做复杂设计编辑器。

内容变成图片：

适合正文结构强、步骤多、清单多，或用户想把主要表达放到图片页里。

输出：

- 封面图；
- 3-8 页图文卡片；
- 正文精简版：100-300 字；
- 每页包含页标题、核心要点、页面文案、视觉建议和生成提示；
- 可导出图片。

验收标准：

- 用户能在笔记生成后选择图片生成方式；
- 用户能选择生成配图或内容变成图片；
- 生成配图至少输出封面图和 3 张配图；
- 内容变成图片至少输出封面图、正文精简版和 3 页图文卡片；
- 生成结果能保存到任务历史；
- 图片生成不改变原始笔记正文，除非用户确认替换。

#### 4.7 任务历史

作用：保存用户每次生成的一组笔记，支持持续使用。

任务历史展示：

- 任务名称；
- 创建时间；
- 场景卡；
- 诊断结果摘要；
- 对应内容目的；
- 生成数量；
- 生成的笔记标题；
- 发布状态；
- 是否已填写反馈；
- 是否已生成优化建议。

笔记状态：

- 草稿；
- 已发布；
- 已反馈；
- 已归档。

验收标准：

- 用户重新登录后能查看历史任务；
- 用户能打开历史任务继续编辑；
- 用户能标记某篇笔记已发布；
- 用户能从历史任务进入发布反馈。

### 主菜单 3：数据反馈

作用：让产品从“生成器”变成“持续优化工具”。

P0 不自动抓取小红书数据，只支持手动回填。

#### 5.1 发布反馈

用户对单篇笔记填写：

- 发布时间；
- 浏览；
- 点赞；
- 收藏；
- 评论；
- 主页访问；
- 私信；
- 关注变化；
- 商品咨询或购买意向；
- 高价值评论；
- 用户主观反馈；
- 截图或备注。

品牌项目重点观察：

- 收藏；
- 评论；
- 私信；
- 商品咨询；
- 购买意向。

个人 IP 重点观察：

- 关注变化；
- 评论质量；
- 私信；
- 互动方向；
- 用户是否记住账号定位。

验收标准：

- 用户能为每篇已发布笔记填写反馈；
- 用户可以只填部分字段；
- 用户能记录高价值评论或关键私信内容；
- 至少填写主观反馈或核心数据后，才能生成优化建议；
- 数据只用于下一轮优化，不作为销售或涨粉承诺。

#### 5.2 优化建议

系统根据资料库、任务内容和反馈数据输出：

- 下一轮内容方向；
- 下一次生成任务建议；
- 可带入下一次生成任务的参数；
- 标题优化方向；
- 正文角度调整；
- 话题调整建议；
- 封面图和配图调整建议；
- 继续测试或暂停的内容方向。

验收标准：

- 优化建议必须说明依据；
- 不只看点赞；
- 必须关联原笔记、内容主线和反馈数据；
- 必须引用关键数据或高价值评论；
- 能被下一次生成任务引用。

## AI 生成策略

### 输入优先级

1. 资料库长期资料；
2. 账号定位；
3. 内容主线；
4. 场景卡类型；
5. 本次手动输入素材；
6. 诊断结果；
7. 本次生成任务要求；
8. 素材条件；
9. 历史发布反馈；
10. 对标账号结构；
11. 平台表达习惯；
12. 通用模板。

不要让通用模板覆盖用户真实信息。

### 输出约束

- 不直接搬运；
- 不伪造案例；
- 不假装已经自动抓取或解析平台数据；
- 不承诺无法证明的效果；
- 不生成明显违规或夸大内容；
- 不使用“全网最”“必爆”“稳赚”等绝对化表达；
- 标题默认不超过 20 个字；
- 正文不得超过 1000 字；
- 正文必须符合用户选择的字数档位；
- 图片生成必须在笔记内容生成后触发；
- 生成配图必须优先匹配用户已有或可补拍素材；
- 内容变成图片必须输出 100-300 字正文精简版和图片页结构；
- 话题必须与正文相关；
- 封面图、配图和图文卡片必须可导出；
- 每篇笔记必须输出可发布质检结果；
- 每篇笔记必须说明对应的诊断依据；
- 每次任务必须给出一个下一步动作和一个复盘指标；
- 输出必须保留人工编辑空间。

## 风险与边界

### 风险 1：登录让 MVP 变重

解决方式：P0 只做最小登录，用于保存用户项目、资料库、任务历史和反馈，不做会员、支付、团队和权限系统。

### 风险 2：项目大类不可更改导致用户选错

解决方式：创建项目时明确提示；选错后新建项目，P1 再考虑复制为新项目。

### 风险 3：资料库填写太重

解决方式：先收必填字段，允许后续补充；内容生产前只拦截真正影响生成质量的关键缺失项。

### 风险 4：内容生成变成泛 AI 文案

解决方式：每篇内容必须绑定资料库、账号定位、内容主线、本次任务和用户真实资料。

### 风险 5：用户误解为销售或涨粉承诺

解决方式：品牌项目只看内容表达和购买意向，个人 IP 只看定位清晰和互动意向。

### 风险 6：图片生成让 MVP 变重

解决方式：P0 只做两种固定图片生成方式：生成配图、内容变成图片；不做开放式文生图和复杂编辑器。

### 风险 7：长内容硬塞正文导致不可发布

解决方式：小红书正文最多 1000 字；如果用户需要把更多内容放进图片，先生成正文，再使用“内容变成图片”生成正文精简版和图片页结构。

### 风险 8：品牌商品图被生成失真

解决方式：品牌项目优先使用用户上传或可补拍的产品素材，不凭空生成虚假的商品细节。

### 风险 9：场景卡过多导致 MVP 变散

解决方式：产品可展示 10 张场景卡方向，但第一轮最小验证只重点跑草稿改写、发布前体检和发布复盘。

### 风险 10：用户误以为系统能自动抓取平台数据

解决方式：P0 明确是手动素材输入，链接、截图和后台图只作为用户提供的诊断素材，不做自动爬取或自动解析承诺。

### 风险 11：诊断结果太泛

解决方式：每次诊断必须落到问题、机会、风险、生成方向、下一步动作和复盘指标，并连接后续 3 篇笔记。
