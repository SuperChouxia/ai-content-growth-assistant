# 内容获客定位助手 - PRD 阶段边界与交付清单

更新日期：2026-06-11

## 结论

当前项目先停在产品需求文档阶段。

暂时不进入：

- 产品设计；
- 低保真线框；
- 高保真视觉；
- 前端开发；
- 后端开发；
- 首批用户执行。

当前要交付的是一套能说明清楚产品方向、P0 范围、输入输出、状态流转、风险边界和验收标准的 PRD 文档。

## 当前 PRD 范围

### 已经确定

- 第一优先用户：服务型个人 IP；
- 当前细分入口：AI/效率工具顾问；
- 产品主价值：内容获客定位判断；
- P0 形态：内容获客定位诊断工作台；
- P0 输出：账号定位诊断、内容主线和选题系统、单篇内容草稿；
- P0 首屏资料字段：8 个必填判断字段；
- 生成顺序：先资料检查，再定位，再选题，再草稿，再人工审核。

### 暂不确定

- 是否做成 SaaS；
- 是否先做服务包；
- 是否进入人工增强验证；
- 是否进入产品设计；
- 是否进入开发；
- 是否需要真实用户试跑。

## PRD 验收标准

当前阶段通过标准：

- 目标用户清楚；
- 核心价值清楚；
- P0 范围清楚；
- 不做什么清楚；
- 输入字段清楚；
- 输出结果清楚；
- 状态流转清楚；
- 人工审核规则清楚；
- 风险边界清楚；
- 暂不进入设计和开发。

当前阶段不要求：

- 可视化线框；
- Figma；
- 高保真页面；
- 可运行原型；
- 代码实现；
- 数据库结构；
- API 设计；
- 真实用户招募；
- 发布和复盘执行。

## 下一步

当前不继续往设计层推进。

后续如果重新打开产品设计阶段，再从以下问题开始：

1. 是否要把 PRD 转成可视化低保真线框；
2. 是否需要 Figma 或本地可运行原型；
3. 是否要先做人工增强验证，再决定开发。
