## 结论

巴布当前定位为面向一人公司、品牌主和个人 IP 的小红书内容工作台。产品用“对话、创作、账号”三个一级模块，帮助用户沉淀账号资料、梳理想法、生成笔记、生成配图并按账号回看历史内容。

MVP v0.9 已完成模型与商业化决策，并将生成模式、积分预估、生成进度、会员、积分包、支付结果、消费记录和异常返还落实为桌面端可交互原型。当前结果适合用户走查、模型盲测和工程化决策，不代表真实 AI、认证、数据库、支付、图片服务或小红书平台能力已经上线。

## 产品一句话

先让巴布理解你的账号，再一起把想法变成可用的小红书笔记和图片。

## 目标用户

### 品牌账号

- 有商品、门店或服务；
- 需要把卖点转成真实使用场景；
- 希望稳定产出内容，不从空白写起；
- 不承诺销售、转化率或平台推荐。

### 个人 IP

- 有专业能力、经历、观点或服务；
- 需要清晰定位、稳定选题和持续表达；
- 希望生成内容更像本人，而不是通用模板；
- 不承诺涨粉、爆款或平台推荐。

## 当前产品结构

### 首页与登录

- 首页只说明产品定位和核心价值；
- “立即开始”打开账号密码登录弹窗；
- 已登录状态可直接进入工作台；
- 当前不做注册、验证码、微信登录和小红书授权。

### 对话

- 三列布局：一级菜单、对话列表、聊天工作区；
- 支持新建、历史搜索和切换；
- 支持快捷问题、消息输入、Enter 发送、等待和原型回复；
- 用于定位、选题、改写和表达检查；
- 对话独立于创作任务，不会自动生成或发布笔记。

### 创作

- 三列布局：一级菜单、账号列表、创作工作区；
- 支持内容主线和商品主线；
- 商品主线展示商品第一张图和标题；
- 生成设置包含标准/高质量模式、三种字数档位、1-5 篇数量和预计积分；
- 生成过程显示搜索、生成和质检进度，失败时返还积分；
- 生成结果按列表预览，点击后进入只读详情；
- 单篇详情支持内容配图或商品展示图、标准或高质量模式以及 1-6 张数量，经过加载状态后展示结果并开放下载。

### 创作历史

- 按当前选中账号展示全部历史笔记；
- 列表项包含封面、标题、摘要、话题和时间；
- 点击后进入只读详情；
- 不显示任务汇总表、新建任务按钮、笔记状态或编辑保存动作。

### 账号

- 三列布局：一级菜单、账号列表、账号资料工作区；
- 支持多个账号搜索和切换；
- 品牌账号使用账号、品牌、商品三步创建；
- 个人 IP 使用账号、IP 两步创建；
- 账号详情区分品牌商品与个人 IP 产品或服务。

### 个人中心

- 左侧底部入口统一命名为“个人中心”，进入后不显示中间上下文栏；
- 右侧整页展示注册邮箱和修改密码表单；
- 退出登录位于右上角，选择“是”返回未登录首页，选择“否”停留当前页；
- 提供月/季/年会员、积分包、微信/支付宝扫码支付状态和消费记录原型。

## 当前核心路径

### 对话路径

**首页 -> 登录 -> 对话 -> 新建或选择历史 -> 输入问题 -> 查看回复 -> 继续追问。**

### 创作路径

**首页 -> 登录 -> 选择账号 -> 选择内容/商品主线 -> 选择生成模式、字数和 1-5 篇数量 -> 确认预计积分 -> 搜索/生成/质检 -> 查看只读详情 -> 选择图片类型、模式和 1-6 张数量 -> 生成并下载。**

### 历史路径

**创作 -> 创作历史 -> 查看当前账号历史笔记 -> 点击笔记 -> 查看只读详情 -> 返回。**

### 账号路径

**账号 -> 新建账号 -> 选择品牌或个人 IP -> 填写资料 -> 保存 -> 查看账号资料。**

### 个人中心路径

**个人中心 -> 查看注册信息，或修改密码，或选择会员/积分包并走查扫码支付，或查看消费记录，或二次确认后退出登录。**

## 当前验证假设

1. 用户会把对话用于想法梳理，把创作用于结构化批量产出；
2. 账号资料和主线选择能提高结果贴合度；
3. 生成结果足够好时，只读查看比编辑保存流程更轻；
4. 单篇 1-6 张配图足以支撑首轮发布准备；
5. 按账号组织创作历史比按任务汇总更容易回看。
6. 个人中心用整块右侧区域承载低频账户操作，比复用三列上下文栏更清楚。

## MVP 边界

- 不做一键搬运、洗稿和自动发布；
- 不做自动评论、私信和获客；
- 不做平台后台数据抓取和持续监控；
- 不做数据看板、发布反馈和自动复盘；
- 不做内容转图片卡片和复杂图片编辑器；
- `v0.9` 只实现会员、积分、支付和账务的前端原型，不接真实收款、订单或账务系统；
- 不承诺爆款、涨粉、销售或转化；
- 当前不进入生产部署。

## 阶段路线

### 阶段 0：MVP v0.8 里程碑

状态：完成。

- 对话、创作、账号三列信息架构收口；
- 账号、创作、历史、详情和配图流程收口；
- 对话列表密度、顶部标题和输入焦点样式收口；
- 个人中心、修改密码和退出登录确认流程收口；
- 需求、设计、技术、品牌和 QA 文档统一；
- 创建 Git 提交和里程碑标签。

### 阶段 0B：MVP v0.9 模型与商业化原型

状态：完成。

- 模型、搜索、质量检查、会员、积分和支付规则收口；
- 标准/高质量生成、积分预估和三阶段进度原型收口；
- 会员、积分包、扫码支付状态、消费记录和异常返还原型收口；
- 笔记复制、图片类型与模式、1-6 张生成和下载入口收口；
- 真实模型、支付、认证、数据库和账务继续保留为工程边界。

### 阶段 1：真实用户走查

- 使用品牌和个人 IP 样本完成任务；
- 观察对话与创作的职责是否易懂；
- 记录主线选择、只读结果和配图数量的阻塞点；
- 只收集影响核心流程的反馈。

### 阶段 1B：模型与成本验证

- 用 3-5 名真实试用者完成 30-50 个盲测任务；
- 比较国内文字、国内图片和海外高质量候选模型；
- 验证至少 80% 的输出可直接使用或只需极少修改；
- 记录每次任务的搜索、模型、质检、图片、存储和支付成本；
- 用真实任务验证每月 1000 赠送积分与 65% 综合毛利目标。

### 阶段 2：工程化决策

- 根据走查结果确认真实 P0；
- 决定是否恢复轻编辑或增加“转为创作”；
- 根据实测确认 AI、图片、搜索、存储、支付和运维成本；
- 确认微信、支付宝扫码支付和积分账本实现范围；
- 确认后再拆正式开发计划。

### 阶段 3：轻量产品化

- 优先实现认证、账号、对话、创作历史和图片任务；
- 使用托管数据库与 Serverless API；
- 小范围内测并观察连续使用；
- 不提前扩展数据复盘和平台自动化。

## 最小验证方式

每位用户完成四个任务：

1. 新建对话并完成一次追问；
2. 选择一个账号和主线生成三篇笔记；
3. 打开一篇历史笔记；
4. 为单篇笔记生成三张配图。

记录完成时间、阻塞点、是否需要解释、至少一篇内容是否可直接使用，以及用户是否愿意再次使用。
