# AI 创作工具 / 内容增长工作台 - 项目总览

更新日期：2026-07-01

文档版本：MVP v0.5

## 结论

本项目不再定义为普通“AI 写稿工具”，而是定义为：

**面向一人公司、品牌主和个人 IP 的小红书内容增长工作台。**

它的核心价值不是替用户多写几篇文案，而是帮助用户用最低验证成本完成一轮内容实验：

**沉淀项目资料 -> 选择场景卡 -> 手动提供素材 -> 先诊断判断 -> 生成 3 篇可发布笔记 -> 单篇生成图片 -> 发布反馈 -> 下一轮优化。**

当前阶段仍然只做市场、运营、产品需求和原型文档；不进入正式开发，不承诺销售、涨粉、爆款或平台推荐。

## 推荐方案

MVP v0.5 保留 v0.4 的内容生产闭环，同时在内容管理前增加“场景卡”入口。

保留不变：

- 左侧主菜单只保留 3 个：项目管理、内容管理、数据反馈；
- 资料库仍然在项目管理内部，是长期资料中枢；
- 资料库包含基础资料、品牌/个人 IP 资料、内容偏好、素材条件、对标参考、生成约束，且每组都可编辑；
- 内容生成仍然是“先选择字数 -> 生成 3 篇笔记 -> 单篇详情里生成配图或内容变成图片”；
- 图片能力是发布闭环里的二段动作，不是独立设计器。

新增收敛：

- 内容管理首页增加场景卡；
- 场景卡不直接等于生成器，而是先诊断再生成；
- P0 不做平台爬取，先让用户手动输入链接、截图、草稿、关键词和后台数据截图；
- 每次场景卡输出只追求一个可发布内容包、一个下一步动作、一个复盘指标。

## 关键依据

用户真正缺的不是“AI 能不能写”，而是：

- 账号现在的问题是什么；
- 该参考谁，但不能照搬什么；
- 这次应该先测试哪个内容方向；
- 这篇笔记能不能发；
- 发完看什么指标；
- 下一篇应该怎么调整。

灵造类产品证明了“公开数据能力 + Agent Skill + 场景 Prompt 工作流”有市场价值，但当前产品不应直接照搬重数据采集和平台解析能力。

对本项目更轻的方式是：

- 先让用户手动提供素材；
- AI 负责结构化诊断、判断和生成；
- 用发布反馈形成下一轮实验；
- 等用户验证愿意持续使用后，再考虑自动采集或深度数据能力。

## 目标用户

### 样本 A：品牌 - 宠物用品

用户特征：

- 有自己的品牌和商品；
- 希望在小红书建立品牌认知；
- 希望内容能承接种草、信任和购买意向；
- 需要把商品卖点讲成真实使用场景。

验证目标：

- 商品卖点能不能被讲清楚；
- 品牌调性能不能被表达出来；
- 内容能不能落到真实养宠场景；
- 用户是否愿意基于内容进一步了解产品。

边界：

**不承诺销售，不承诺转化率，不做店铺运营。**

### 样本 B：个人 IP

用户特征：

- 有专业能力、经历、观点或服务方向；
- 希望在小红书持续发布笔记；
- 希望通过内容吸引关注、互动或私信；
- 过去的问题是定位不清、选题散、内容不像自己。

验证目标：

- 账号定位能不能一句话说清；
- 内容主线能不能支撑持续发布；
- 笔记能不能表达个人经历、观点和专业能力；
- 用户是否愿意发布并观察互动反馈。

边界：

**不承诺涨粉，不承诺爆款，不承诺平台推荐。**

## 信息架构

### 项目管理

用于管理项目和资料库。

包含：

- 项目列表；
- 创建项目；
- 项目首页；
- 资料库；
- 定位与内容主线。

### 内容管理

用于完成场景诊断和内容生产。

包含：

- 场景卡入口；
- 手动素材输入；
- 诊断结果；
- 生成任务；
- 任务历史；
- 笔记详情；
- 单篇图片生成。

### 数据反馈

用于把发布结果转成下一轮实验。

包含：

- 发布反馈；
- 优化建议；
- 下一轮内容实验建议。

## 场景卡设计

P0 场景卡不做成复杂工作流市场，只作为内容管理里的入口。

建议保留 10 张卡：

1. 主页诊断；
2. 找对标账号；
3. 爆文拆解；
4. 关键词洞察；
5. 草稿改写；
6. 发布前体检；
7. 7 天发布计划；
8. 发布复盘；
9. 内容知识库；
10. 变现判断。

每张场景卡统一输出：

- 诊断判断：先说明当前问题、机会和不建议做什么；
- 可发布内容包：默认进入 3 篇笔记生成流程；
- 下一步动作：告诉用户下一步只做一个动作；
- 复盘指标：告诉用户发完后看一个核心指标。

第一轮最小验证建议先重点验证 3 张卡：

- 草稿改写；
- 发布前体检；
- 发布复盘。

## 当前不做什么

- 不做一键搬运；
- 不做洗稿；
- 不做自动发布；
- 不做自动私信；
- 不做平台爬取；
- 不做自动解析小红书、抖音、公众号数据；
- 不做大规模账号库；
- 不做完整素材库自动采集；
- 不做复杂 A/B 测试；
- 不做完整会员体系；
- 不做独立图片设计器；
- 不承诺爆款；
- 品牌项目不承诺销售；
- 个人 IP 不承诺涨粉。

## 最小验证方式

当前不急着扩展功能，也不急着做完整 SaaS。

先用两个样本和三张场景卡验证：

- 品牌 - 宠物用品；
- 个人 IP - 知识分享；
- 草稿改写；
- 发布前体检；
- 发布复盘。

每次验证只看三件事：

1. 是否得到一个用户愿意发布的内容包；
2. 是否得到一个明确下一步动作；
3. 是否得到一个用户愿意回填的复盘指标。

## 阶段路线

### 阶段 0：方案收敛

状态：当前阶段。

目标：

- 统一 MVP v0.5 口径；
- 更新 PRD 和原型文档；
- 判断是否需要更新本地可视化原型；
- 不进入开发。

### 阶段 1：文档与原型验证

目标：

- 用本地原型走通 3 个主菜单；
- 让场景卡自然进入内容管理；
- 检查“诊断 -> 生成 3 篇 -> 图片 -> 反馈”的路径是否顺。

### 阶段 2：人工增强测试

目标：

- 用少量真实或半真实样本测试；
- 先人工处理素材输入和诊断质量；
- 不急着自动化平台采集。

### 阶段 3：轻量产品化

目标：

- 如果用户愿意持续使用，再考虑账号体系、任务保存、AI 生成接口、图片生成接口和轻量数据结构；
- 仍然保持小步迭代。
