# AI 创作工具 / 内容增长工作台 - 运营叙事定位

更新日期：2026-07-01

文档版本：MVP v0.5

## 结论

当前对外叙事不要说成“AI 小红书写作工具”，也不要说成“爆款生成器”或“代运营服务”。

推荐叙事：

**面向一人公司、品牌主和个人 IP 的小红书内容增长工作台。**

一句话表达：

**帮你把已有资料、草稿、截图和反馈，转成诊断判断、3 篇可发布笔记和下一轮内容实验。**

## 推荐方案

### 主叙事

不是帮你多写几篇内容，而是帮你完成一轮低成本内容实验。

重点回答四个问题：

1. 现在卡在哪里：账号、草稿、选题、主页、对标还是复盘；
2. 为什么这样判断：基于你的资料、截图、草稿和反馈；
3. 这次先发什么：生成 3 篇可发布小红书笔记；
4. 发完看什么：只盯一个复盘指标，再决定下一步。

### 品牌叙事

**把商品卖点和真实使用场景，转成小红书能看懂、能收藏、能评论的内容实验。**

边界：

- 不承诺销售；
- 不承诺转化率；
- 不做店铺代运营。

### 个人 IP 叙事

**把专业能力、经历和观点，转成账号定位、内容主线和可持续发布的小红书笔记。**

边界：

- 不承诺涨粉；
- 不承诺爆款；
- 不承诺平台推荐。

## 关键依据

### 依据 1：用户缺的是判断，不只是文案

“写内容”只是输出层。用户更常见的问题是：

- 不知道这个账号现在该先解决什么；
- 不知道自己的草稿能不能发；
- 不知道该参考谁，又怕照搬；
- 不知道发完以后看什么；
- 不知道下一篇怎么调整。

### 依据 2：场景卡比空白写作框更接近真实使用

主页诊断、草稿改写、发布前体检、发布复盘这些场景，比“新建文案”更容易让用户知道自己该输入什么、会得到什么。

### 依据 3：轻量素材输入更适合 MVP

当前不做平台爬取和自动解析。用户手动提供链接、截图、草稿、关键词、后台数据截图，已经足够验证诊断和生成价值。

## 叙事框架

### 第一层：问题

品牌项目常见问题：

- 有商品，但笔记只是在介绍参数；
- 有品牌调性，但内容表达不稳定；
- 想做种草，但不知道怎么落到真实场景；
- 看了很多同类品牌账号，但不知道哪些能学；
- 想在小红书产生销售，但第一步其实是先让用户看懂并产生兴趣。

个人 IP 常见问题：

- 有经历和能力，但账号讲不清；
- 发的内容像泛泛干货，没有个人辨识度；
- 选题想到哪发哪，难以持续；
- 看了很多对标账号，但不知道自己能学什么；
- 想吸引关注和互动，但内容没有稳定主线。

### 第二层：转化

从：

**想到什么发什么**

变成：

**围绕目标用户、卖点、场景和信任持续发布。**

从：

**模仿爆款表达**

变成：

**提炼对标结构，再写回自己的产品、经历和判断。**

从：

**把内容当输出任务**

变成：

**把内容当一次可复盘的实验。**

### 第三层：结果

用户每次应该得到的不是一堆孤立文案，而是：

- 一个诊断判断；
- 一个可发布内容包；
- 一个下一步动作；
- 一个复盘指标；
- 一条可延续的内容实验线索。

## 对外表达库

### 标准一句话

面向一人公司、品牌主和个人 IP 的小红书内容增长工作台，把资料、草稿、截图和反馈转成诊断判断、3 篇可发布笔记和下一轮实验。

### 更短版本

先判断内容该怎么改，再生成 3 篇能发的小红书笔记。

### 更直接版本

不是帮你写爆款，而是帮你知道这次该发什么、为什么发、发完看什么。

### 品牌版本

帮品牌项目，把商品卖点和使用场景，变成小红书种草内容实验。

### 个人 IP 版本

帮个人 IP，把专业能力、经历和观点，变成定位清楚、能持续发布的小红书笔记。

### 场景卡版本

主页诊断、草稿改写、发布前体检、发布复盘，一次只解决一个内容问题。

## 用户语言

运营表达应尽量贴近用户会说的话。

### 品牌方会说

- 我有产品，但不知道小红书该怎么发；
- 我不想笔记只是在介绍功能参数；
- 我想让用户知道这个产品适合什么使用场景；
- 我看了很多同类品牌账号，但不知道怎么学；
- 我想通过小红书带来销售，但也知道第一步是先把品牌和产品讲清楚。

### 个人 IP 会说

- 我知道自己会什么，但账号不知道该怎么定位；
- 我不想再发泛泛的知识点；
- 我看了很多对标账号，但不知道自己能学什么；
- 我有经历和观点，但写出来不像内容；
- 我想让内容带来更精准的关注、评论或私信。

### 用户不太会说

- 我需要一个 AI 内容中台；
- 我需要多模态营销自动化；
- 我需要全链路智能增长系统；
- 我需要 AIGC 私域矩阵闭环。

## 主张与禁区

### 应该强调

- 场景卡；
- 诊断判断；
- 资料库；
- 账号定位；
- 内容主线；
- 商品卖点拆解；
- 专业能力表达；
- 真实场景内容化；
- 对标结构参考；
- 发布前体检；
- 发布后复盘；
- 人工判断和 AI 辅助结合。

### 不应该强调

- 爆款；
- 自动涨粉；
- 自动成交；
- 一键搬运；
- 洗稿改写；
- 自动获客；
- 自动发布；
- 自动抓取平台数据；
- 完整代运营；
- 复杂会员体系。

## 最小验证方式

对外测试时，不要一次讲完整平台。

优先用三句话解释：

1. 你先选一个场景，比如草稿改写、发布前体检或发布复盘；
2. 你给我一段草稿、一张截图、一个链接或一张后台数据图；
3. 系统先给诊断，再生成 3 篇能发的笔记，并告诉你发完看什么。
