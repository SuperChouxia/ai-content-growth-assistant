# AI 创作工具 / 内容增长工作台 - 现阶段策略边界

更新日期：2026-07-01

文档版本：MVP v0.5

## 结论

当前产品定位从“小红书定位与内容验证助手”升级为：

**面向一人公司、品牌主和个人 IP 的小红书内容增长工作台。**

这个升级不是扩大 MVP 范围，而是把产品价值从“AI 写稿”前移到“诊断、判断、生成和复盘”。

当前仍然不进入正式开发，不做平台爬取，不做自动解析，不做大规模账号库，不做完整会员体系。先用用户手动提供的链接、截图、草稿、关键词和后台数据截图，完成最小内容实验闭环。

## 已确认事实

- 目标用户仍然是有产品、有服务、有品牌或有专业能力的人。
- 品牌和个人 IP 都可以先用小红书作为首发平台。
- 用户痛点不只是缺文案，而是账号定位、对标参考、选题判断、发布前判断和发布后复盘都不清楚。
- P0 核心闭环仍然是：选择字数 -> 生成 3 篇笔记 -> 单篇详情生成配图或内容变成图片。
- 图片能力是发布闭环里的二段动作，不是独立设计器。
- 资料库仍然是项目管理里的长期资料中枢，所有分组都应可编辑。
- 左侧主菜单只保留：项目管理、内容管理、数据反馈。
- 品牌项目不承诺销售，只验证品牌表达、商品种草和购买意向。
- 个人 IP 不承诺涨粉，只验证定位清晰度、内容主线、互动意向和持续发布意愿。

## 合理推断

- 用户愿意为“判断和下一步动作”付费的概率，高于只为“生成一篇文案”付费。
- 灵造类产品的强点说明：场景 Prompt 工作流比单一编辑器更容易让用户理解价值。
- 当前产品不适合一开始照搬重数据采集能力，因为平台爬取、解析和数据合规都会显著增加成本。
- 手动素材输入足以支撑 MVP 验证：链接、截图、草稿、关键词、后台截图都可以作为第一阶段素材入口。
- 场景卡适合作为内容管理的入口，但不应该变成新的一级菜单。
- 场景卡的结果应该先给诊断，再进入生成 3 篇笔记，而不是直接生成一堆内容。

## 待验证假设

### 假设 1：场景卡能降低用户启动成本

需要验证：

- 用户是否比“新建生成任务”更容易理解“主页诊断、草稿改写、发布复盘”等场景；
- 场景卡是否能让用户更快知道这次要提供什么素材；
- 用户是否认可“先诊断，再生成”的节奏。

### 假设 2：手动素材输入足以完成 MVP

需要验证：

- 链接、截图、草稿、关键词和后台数据截图是否足够 AI 做判断；
- 用户是否愿意手动上传或粘贴这些素材；
- 手动输入是否比平台授权更轻、更容易被接受。

### 假设 3：每次只输出一个内容实验更适合一人公司

需要验证：

- 一个可发布内容包是否比复杂内容矩阵更容易执行；
- 一个下一步动作是否能推动用户发布；
- 一个复盘指标是否能提高用户回填反馈的概率。

### 假设 4：不做平台爬取也能形成差异化

需要验证：

- 用户是否把价值感放在诊断判断和可发布内容上；
- 没有自动采集时，产品是否仍然比通用 AI 写作工具更有用；
- 场景卡和资料库是否足够形成产品记忆点。

## 机会

### 机会 1：从 AI 写稿切到内容增长工作流

通用 AI 写作工具容易同质化。更有机会的切入口是帮用户完成：

**诊断 -> 生成 -> 发布 -> 反馈 -> 下一轮实验。**

### 机会 2：先服务一人公司和自媒体获客者

这类用户既需要效率，也需要判断；既没有团队代运营，也不能承受复杂工具成本。轻量工作台比完整营销 SaaS 更贴近他们。

### 机会 3：用场景卡承接高频问题

主页诊断、草稿改写、发布前体检、发布复盘比“空白写作框”更接近真实使用场景，也更利于后续沉淀可复用工作流。

## 风险

### 风险 1：场景卡过多导致产品变散

应对方式：

P0 可以展示 10 张卡作为方向，但最小验证先重点跑 3 张：草稿改写、发布前体检、发布复盘。

### 风险 2：用户误以为可以自动抓取平台数据

应对方式：

明确 P0 是手动素材输入，不做小红书授权、自动抓取或自动解析。

### 风险 3：诊断结果太虚

应对方式：

每次输出必须落到一个可发布内容包、一个下一步动作、一个复盘指标。

### 风险 4：产品被理解为代运营或增长承诺

应对方式：

持续强调不承诺销售、涨粉、爆款，只降低定位、生产和复盘成本。

## 最小验证方式

先不用完整开发，只用 PRD、可视化原型和半人工样本验证：

1. 选择一个品牌样本和一个个人 IP 样本；
2. 只跑 3 张场景卡：草稿改写、发布前体检、发布复盘；
3. 每张卡都要求用户手动提供素材；
4. 输出诊断判断；
5. 再进入“选择字数 -> 生成 3 篇笔记”；
6. 用户选择其中一篇继续生成配图或内容变成图片；
7. 发布后只回填一个核心指标和一句主观反馈。

## 建议动作

1. 当前统一项目版本为 MVP v0.5；
2. 项目表达升级为“AI 创作工具 / 内容增长工作台”；
3. PRD 中加入场景卡、手动素材输入、诊断结果和最小复盘指标；
4. 原型文档中加入“内容管理 -> 场景卡 -> 诊断结果 -> 生成 3 篇笔记”的路径；
5. 本地可视化原型后续需要同步更新，但在用户确认文档前不急着改代码；
6. GitHub 仍保持本地确认后再同步。
